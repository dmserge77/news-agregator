# Структура проекта AI News Hub

Проект представляет собой статический сайт-агрегатор новостей, вакансий и заказов, который генерируется Python-скриптом `collector.py` и публикуется через GitHub Pages.

## Корневая директория (C:\Users\Я\Documents\MultiTool\HomeChats\Chat-8)

| Файл / Папка | Назначение |
|---|---|
| `collector.py` | **Главный мозг проекта.** Скрипт на Python. Парсит RSS/API, собирает данные, фильтрует их и генерирует HTML-страницы. |
| `CHANGELOG_13_09_2026.md` | Файл с историей изменений и итогами работ (создан сегодня). |
| `favicon.svg` | Иконка сайта (глобус). |
| `index.html` | **Главная страница.** Содержит навигацию и общую сводку. Генерируется скриптом, но заголовок (head) правится вручную. |
| `_category_template.html` | **Главный шаблон.** Скелет HTML для всех страниц категорий (ai/, vibe/ и т.д.). Содержит `%%ПЕРЕМЕННЫЕ%%`, которые заменяются скриптом. |
| `dist/` | **Папка сборки (Артефакт).** Создается скриптом `collector.py`. Содержит **готовые к публикации** HTML-файлы. Именно эту папку GitHub Actions загружает на сервер. |
| `.github/` | Папка настроек CI/CD (GitHub Actions). |
| `ai/`, `vibe/`, `agent/`, `platform/`, `jobs/`, `orders/` | **Папки категорий.** Содержат сгенерированные страницы новостей по темам. |

## Детальный разбор содержимого

### 1. Папки категорий (ai/, vibe/, jobs/ ...)
Внутри каждой такой папки (например, `C:\Users\Я\Documents\MultiTool\HomeChats\Chat-8\ai`) находятся три файла, которые создает `collector.py`:

*   `index.html` — Сама страница категории (например, «Нейросети»). В ней только контент, шапка и подвал берутся из `_category_template.html`.
*   `data.js` — Файл с данными. Содержит JSON-массив `window.NEWS_DATA` со всеми новостями этой категории. Подключается скриптом в HTML для работы фильтров (язык, тип).
*   `news.json` — Сырой JSON со всеми данными. Нужен для работы скрипта при следующей сборке (чтобы не потерять ручные правки или старые новости).

### 2. Папка .github/workflows/
Здесь живет логика автоматического деплоя.
*   `deploy.yml` — Файл конфигурации GitHub Actions. Описывает, что делать при пуше в репозиторий:
    1. Запустить `python collector.py`.
    2. Собрать папку `dist`.
    3. Отправить её на GitHub Pages.

### 3. Папка dist/ (Результат сборки)
Эту папку **нельзя редактировать вручную**, она пересоздается каждый раз при запуске `collector.py`.
*   Когда вы запускаете `python collector.py`, скрипт сначала удаляет старое содержимое `dist` (или обновляет файлы).
*   Затем он копирует туда `index.html` и все папки категорий (`ai`, `vibe`...), но кладет туда **только** `index.html` и `data.js` из каждой папки.
*   Именно содержимое `dist/` видит пользователь в интернете.

### Как происходит обновление (Workflow)
1.  Вы меняете код в `collector.py` или шаблон в `_category_template.html`.
2.  Запускаете `python collector.py` на своем ПК.
3.  Скрипт генерирует/обновляет файлы внутри папок `ai/`, `vibe/` и т.д., а также создает папку `dist/`.
4.  Вы делаете `git add .`, `git commit` и `git push`.
5.  GitHub видит пуш, запускает `.github/workflows/deploy.yml`.
6.  Actions на сервере снова запускает `collector.py` (чтобы данные были свежими) и публикует папку `dist/`.

**Важно:** Если вы изменили только `index.html` (главную) вручную, не забудьте закоммитить его отдельно, так как `collector.py` его обычно не трогает при пересборке категорий. Если вы изменили `_category_template.html`, нужно запустить `collector.py`, чтобы изменения попали во все файлы категорий.
