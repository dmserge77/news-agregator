# _snapshots — страховка накопителя новостей

## Зачем это здесь

Накопители `<категория>/news.json` **не попадают в git** (см. `.gitignore`:
`**/news.json`) и живут только в кэше GitHub Actions.

Кэш Actions **удаляется после 7 дней без обращений**. Сборка идёт 6 раз в сутки,
поэтому обычно он всегда свежий — но если workflow сломается или проект встанет
на паузу, история обнулится: останутся только последние 20–50 записей из лент
вместо 90 дней накопленного.

Снимок в репозитории это страхует: он в git, значит переживёт и чистку кэша,
и потерю машины.

## Как снять снимок

```bash
python snapshot.py save --note "причина или повод"
```

Появится `_snapshots/news-ГГГГ-ММ-ДД_ЧЧММ.json.gz` — один сжатый файл со всеми
8 категориями. 1400 записей занимают ~166 КБ.

## Как восстановить

```bash
python snapshot.py list                                # посмотреть, что есть
python snapshot.py restore _snapshots/<файл>.json.gz   # разложить обратно
```

Скрипт работает в два этапа: сначала читает и проверяет снимок целиком, только
потом пишет файлы. Это защита от повторения истории, когда массовая миграция
потеряла 701 запись, записав файл раньше времени.

Проверено 15.09.2026: намеренно испорченные `agent` и `platform` восстановились
побайтово точно — все 8 категорий совпали с резервной копией.

## Когда снимать

- перед крупной правкой `collector.py` или фильтров;
- перед массовой чисткой накопителя;
- перед стартом нового проекта на тех же данных;
- просто раз в неделю, для спокойствия.

Снимки — обычные файлы, старые можно удалять: `git rm _snapshots/<старый>.json.gz`.
