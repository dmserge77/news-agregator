

# AI News Hub
Агрегатор новостей, вакансий и заказов по теме нейросетей, вайбкодинга, ИИ-агентов и связанных платформ.


> Основано на [agents.md](https://agents.md/) — стандарт описания проектов для AI-ассистентов.

## Как вносить изменения

1. **В collector.py** — логика парсинга, фильтрации, генерации страниц, а также **шаблон главной страницы** (внутри f-строки в функции сборки главной).
2. **В _category_template.html** — верстка и JS всех страниц категорий
3. После любых правок запустить `python collector.py` для перегенерации всех файлов
4. commit только когда явно попросит пользователь

**Важно:** корневой `index.html` генерируется скриптом и перезаписывается при каждом запуске `collector.py`. Править его руками бессмысленно — правки нужно вносить в шаблон внутри `collector.py`.

## Резервные копии

Перед существенными правками делай копии **редактируемых** файлов в папку `_backup/`
(она в `.gitignore` и в репозиторий не попадает). Копировать нужно только те файлы,
которые правятся руками, — генерируемые не имеет смысла, их пересоздаёт `collector.py`.

Формат имени: `<имя-файла>_<ГГГГ-ММ-ДД>.<расширение>`

| Копировать | Не копировать |
|---|---|
| `collector.py` | `index.html` (генерируется) |
| `_category_template.html` | `<категория>/index.html` (генерируется) |
| `about/index.html` | `<категория>/data.js`, `<категория>/news.json` (генерируются) |

Пример:
```bash
cp collector.py _backup/collector_2026-09-14.py
```

Основной механизм отката — всё же git (`git checkout <хеш> -- <файл>`, `git revert`).
Папка `_backup/` нужна как дополнительная страховка — копии видно глазами на диске.

## Структура проекта

| Файл | Назначение |
|---|---|
| `collector.py` | Автосборщик: парсит RSS/API, раскладывает новости/вакансии/заказы по папкам |

## Автообновление и сторож

Расписание GitHub Actions **ненадёжно**: cron ставит запуски в очередь, может задержать
на 30–60 минут или вообще пропустить при нагрузке. На практике запуск в 22:00 МСК
не состоялся вовсе.

Поэтому расписание продублировано сторожем:

1. `deploy.yml` — сборка по слотам каждые 4 часа (МСК 02, 06, 10, 14, 18, 22),
   плюс на push и вручную.
2. `watchdog.yml` — запускается каждый час в :45. Смотрит время последней сборки
   **на живом сайте** и сравнивает с началом текущего слота:
   - данные свежие → ничего не делает;
   - данные устарели → дёргает `workflow_dispatch` и перезапускает сборку.
     При следующем часе проверка повторится, пока данные не обновятся;
   - **время прочитать не удалось → тоже перезапускает.** Раньше сторож в этом
     случае молча выходил, и «не смог прочитать» выглядело как «всё хорошо».

Слоты и допуск задаются в `watchdog.py`: `SLOT_HOURS` (часы по МСК) и
`GRACE_MINUTES` (сколько ждать после начала слота, прежде чем считать данные устаревшими).
Сторожу нужны права `actions: write` — они указаны в `watchdog.yml`.

Проверить сторожа локально:
```bash
GITHUB_TOKEN=<токен> python watchdog.py
```

### Ловушки, на которые уже наступили

Эти три пункта выглядят как мелочи, но каждый из них один раз ломал сторожа:

1. **Не читать локальный `dist/ai/data.js`.** Он остаётся от прошлого запуска
   `collector.py` и бывает на много часов старше того, что уже опубликовано.
   Сторож однажды увидел локальные `18:38` вместо онлайн `00:48` и зря дёрнул сборку.
   Единственный источник — живой сайт.
2. **Обходить кэш GitHub Pages.** Ответы отдаются с `Cache-Control: max-age=600`,
   поэтому запрос идёт с `?nocache=<время>` и заголовком `Cache-Control: no-cache`.
   Иначе можно 10 минут видеть старый ответ и опять дёрнуть сборку.
3. **Права токена.** `permissions: actions: write` обязателен, иначе
   `workflow_dispatch` возвращает 401/403 и перезапуск молча не происходит.
   Именно поэтому сторож печатает код ответа и подсказку при ошибке.


## Фильтрация: только про ИИ

Сайт — агрегатор **исключительно про ИИ**. Всё остальное отбрасывается.

- `has_ai_signal(text)` — ищет сильные ИИ-маркеры (`AI_STRONG` + `AI_NAMES` + отдельное слово «AI»).
- `is_ai_relevant(text, cat)` — пропускает материал, только если сигнал есть.
  Дополнительно отсекает бытовые ложные срабатывания (`FALSE_POSITIVES`: стиральные машины,
  дизайн интерьера и т.п., где «ИИ» — маркетинговая приписка).
- `classify()` возвращает `None`, если материал вообще не про ИИ — такие записи не сохраняются.
- Категории `jobs` и `orders` проверку не проходят: у них свои фильтры
  (`is_real_ai_job`, логика в `fetch_fl_orders` и т.д.).
- **Вакансии из RSS не берутся вообще.** `parse_rss()` перенаправляет `cat == "jobs"`
  в `misc`: настоящие вакансии приходят только с hh.ru. Иначе в рубрику просачивались
  обычные статьи.
- Короткие ИИ-названия (`AI_NAMES_WORD`: `llama`, `sora`, `grok`, `qwen`, `xai`,
  `mistral`) ищутся **отдельным словом**. Иначе `llama` ловится в домене
  `wisellama.rocks` из ссылок Hacker News.

### Ловушки ключевых слов (уже наступали)

1. **Не добавлять в `CAT_KEYWORDS["jobs"]` словоформы `работа` / `подработка`.**
   Они ловятся внутри «работать», и в рубрику «Вакансии» уехало 33 статьи:
   «Россиянам придётся работать до 4 месяцев ради iPhone», мониторы Asus,
   планшеты Xiaomi. Только точные формы: `работа вахтой`, `работа удалённо`.
2. **Не подключать источники без темы ИИ.** ТАСС Наука давала научпоп
   (рачки, ITER, чёрные дыры) — он не проходил фильтр и оседал мусором
   даже в вакансиях.
3. **Накопитель не чистится сам.** Фильтр проверяет только новые поступления,
   поэтому старый мусор возвращался в каждую сборку (однажды накопилось 47% набора).
   Шаг 2 в `main()` теперь при каждой сборке переводит такое в `unfiltered`.

### Мёртвые источники (`DEAD_SOURCES`)

Убранный из `FEEDS` источник **не исчезает с сайта**: его материалы уже лежат
в накопителях и продолжают публиковаться. Именно так ТАСС Наука «висел на главной»
уже после удаления из списка лент.

Поэтому в `collector.py` есть набор `DEAD_SOURCES` — записи этих источников
отбрасываются в **двух местах**:
- `parse_rss()` — на входе (если лента случайно вернётся в `FEEDS`);
- шаг 2 в `main()` — при загрузке накопителя, счётчик печатается как `[чистка]`.

Текущий список: `ТАСС Наука` (научпоп не про ИИ), `NYT Tech` (404),
`Cossa` (закрылась), `AWS` (лента не отдаётся), `ComNews` (по 1 записи, и та не про ИИ).

**`ComNews` не подключать НИКОГДА** — по прямому указанию пользователя.

**`vc.ru` в этом списке был ошибочно.** Лента живая, материалы про ИИ бывают —
источник снова в `FEEDS`, но берём **только теги** `/rss/tag/ai` и `/rss/tag/нейросети`:
общая лента тащит бизнес, маркетинг и личные истории, которые фильтр всё равно не пропустит.
Не удалять vc.ru из `FEEDS` без проверки — пользователь ценит этот источник.

**Порядок удаления источника:** убрать из `FEEDS` → добавить в `DEAD_SOURCES` →
пересобрать (шаг 2 сам вычистит накопитель).

### SEO-мусор в тегах (`is_seo_spam`)

ИИ-теги vc.ru забиты рекламными заголовками вида «нейросеть для X бесплатно:
промпт и сервисы» — один автор залил 14 почти одинаковых за ночь. Плюс пустышки
вроде «Запись в сообществе AI».

Для них есть `SEO_SPAM` + `is_seo_spam()`, применяется **только** к источникам
из `SPAM_FILTER_SOURCES` (`{"vc.ru"}`), чтобы не задеть обычные ленты.
Главный маркер — слово `бесплатно` в заголовке: реальные статьи так не называют.
Из 34 записей vc.ru фильтр отсеивает 16, оставляя 18 нормальных.

Важно: фильтр работает **на входе**, поэтому записи, успевшие попасть в накопитель
до его введения, надо вычистить отдельным скриптом.

### Кириллица в URL лент

`urlopen` не умеет кодировать не-ASCII в адресе и падает с
`'ascii' codec can't encode`. Лента `vc.ru/rss/tag/нейросети` из-за этого не читалась.
В `fetch_url()` добавлен `quote(url, safe=":/?#[]@!$&'()*+,;=%~")` — кодирует
только не-ASCII, обычные адреса не трогает.

Если материал про ИИ, но не подходит ни под одну основную категорию — он попадает в «Солянку».

## Солянка (`misc`)

Общая рубрика для всего ИИ-шного, что не влезло в основные категории.

Подрубрики (`MISC_TYPES`, определяются через `classify_misc()`):

| Ключ | Название | Что попадает |
|---|---|---|
| `raznoe` | 📰 Разное | всё остальное, что связано с ИИ |
| `curio` | 🤪 Курьёзы | шутки, мемы, нелепые истории, скандалы, фейлы (`CURIO_MARKERS`) |
| `unfiltered` | 🍺 Не фильтрованное | всё, что НЕ прошло проверку на тему ИИ |

**Отсекается:** «советы», «лайфхаки», «как правильно» — мы не советуем, мы оповещаем.

### «Не фильтрованное» — карантин вместо удаления

Материал, не прошедший `is_ai_relevant()`, **не выбрасывается, а уезжает** в
подрубрику `unfiltered`. Причина: удалять жалко, а держать в тематических рубриках
нельзя — иначе рубрика «Нейросети» заполняется статьями про рачков и видеокарты.

Туда же попадают:

- записи мёртвых источников (`NYT Tech`, `Cossa`, `AWS`, `ComNews` — лент уже нет в `FEEDS`);
- RSS-статьи, попавшие в `jobs` (вакансии приходят только с hh.ru);
- старые записи из накопителя, которые перестали проходить фильтр.

Перевод происходит в `main()`, шаг 2: у записи меняется `cat` на `misc`
и ставится `misc_type = "unfiltered"`. Запись остаётся в общем потоке,
и шаг 5 раскладывает её в папку `misc/`.

**Как выглядит на сайте:** отдельная кнопка в `#miscBar` —
«🍺 Не фильтрованное». Пользователь видит, что это необработанный поток.

## Есть заказ (`orders`)

Единственный источник заказов — `fetch_fl_orders()` (FL.ru). **Через RSS заказы не приходят:**
в `CAT_KEYWORDS["orders"]` намеренно пустой список, иначе статьи про фриланс с Habr
попадали бы в рубрику заказов.

Заказ проходит, если он про ИИ **или** про сайты (`is_ai_order()`):

- сайты проходят **без требования ИИ** — веб-разработка это отдельное направление рубрики;
- ИИ-заказы проверяются тем же `has_ai_signal()`, что и новости;
- дополнительно проходят парсинг, боты, автоматизация;
- отсекаются SEO/Директ/лидоген и статьи (маркеры «объявил», «на днях», «как я…»).

Подрубрики (`ORDER_TYPES`, определяются через `classify_order()`), **порядок проверки важен:**

| Ключ | Название | Что попадает |
|---|---|---|
| `sites` | 🌐 Сайты | сайты, лендинги, вёрстка, CMS, интернет-магазины, CRM — с ИИ и без |
| `prompts` | ✍️ Промты | промпты, промпт-инжиниринг, настройка AI-сервисов |
| `audio` | 🎧 Видео и аудио | озвучка, дубляж, липсинк, видео, Reels, монтаж, анимация |
| `media` | 🎨 Изображения | нейрофото, генерация картинок, иллюстрации, баннеры, ретушь |
| `automate` | 🔧 Автоматизация | парсинг, боты, скрипты, интеграции, выгрузки |
| `ai` | 🤖 AI-разработка | всё остальное про ИИ (fallback) |

`SITE_MARKERS` — маркеры веб-разработки. Они проверяются **первыми**, поэтому заказ
с сайтом и ИИ одновременно попадёт в «Сайты», а не в «AI-разработку».

Старые заказы, не проходящие по текущим правилам, отбрасываются при загрузке накопителя
(шаг 2 в `main()`) — иначе мусор возвращался бы в каждую сборку.
